# M1.2 数据模型与建表

## 1. 任务背景
M1.1 已建立 SQLite 连接。本功能点按 TECH.md 第 4 节落地数据模型：任务四型（tasks）、催办信息（follow_ups）、速记（inbox）、文档（documents，v2 用，先行建表）、配置（settings）。

## 2. 目标
- 服务启动时自动执行建表迁移
- 5 张表 + 必要索引存在，字段与 TECH.md 一致

## 3. 需求
- tasks：id/title/type(main|side|follow|idea)/status(todo|doing|done|archived)/priority/ddl/milestone/tags/note/created_at/updated_at/done_at
- follow_ups：task_id 外键级联删除、person、next_follow_date、urge_count、last_urged_at
- inbox：id/content/tags/created_at/converted_task_id
- documents / settings 先行建好（v2 直接用）
- 索引：tasks(status)、tasks(ddl)、follow_ups(next_follow_date)
- 幂等：IF NOT EXISTS，重启不报错

## 4. 产出
- `server/src/db/schema.ts`：`migrate()` 函数，含全部 DDL 与 3 个索引
- `server/src/index.ts`：启动时调用 `migrate()`

## 5. 实现方案
初版 schema 一次性 exec；文件头注释约定后续用 SQLite `user_version` 做递增迁移，避免早期过度设计迁移框架。外键依赖 M1.1 已开启的 `foreign_keys = ON`（级联删除 follow_ups 依赖它）。

## 6. 遇到的报错及解决方案
| 报错/问题 | 原因 | 解决方案 |
|-----------|------|----------|
| `node -e` 内联验证脚本语法错误 | PowerShell 把双引号/反斜杠转义吃掉 | 改为写临时 `verify-m12.mjs` 脚本文件执行，验证后删除 |

- `follow_ups cols: task_id,person,next_follow_date,urge_count,last_urged_at` ✅
