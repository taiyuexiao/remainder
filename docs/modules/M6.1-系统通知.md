# M6.1 Windows 系统通知（Tauri 版）

## 1. 任务背景
M6 后端提醒队列早已就绪，浏览器版 Toast 轮询在 App.tsx。Tauri 打通后，把提醒出口升级为 Windows 原生通知（通知中心可回看，不打断工作），且必须**主窗口关闭时也能收到**。

## 2. 目标
- 任务到点 → Windows 右下角原生通知
- 主窗口关闭、只剩桌面小组件时依然能收到通知

## 3. 需求
- 轮询 `/api/notifications` 的出口放在**常驻的桌面小组件**（WidgetPage），30s 一次
- 主窗口（App）在 Tauri 环境不再轮询（避免与小组件竞争清空队列导致互相吃通知）；浏览器环境保持 Toast 不变
- 首次使用自动申请通知权限

## 4. 产出
- `desktop/src/notify.ts`：`notifyNative(title, body)`（检测 Tauri 环境、申请权限、发通知，失败静默）
- `desktop/src/pages/WidgetPage.tsx`：新增提醒队列轮询 effect（30s，逐条原生通知后清空队列）
- `desktop/src/App.tsx`：Tauri 环境跳过轮询（`isTauriEnv` 判断），浏览器环境逻辑不变

## 5. 实现方案
架构决策：提醒轮询唯一出口 = 桌面小组件（它永驻桌面层、用户不会关），主窗口只是临时界面。这样"关了主窗口就收不到提醒"的问题从结构上不存在。Tauri 环境检测用 `'__TAURI_INTERNALS__' in window`。

## 6. 遇到的报错及解决方案
| 报错/问题 | 原因 | 解决方案 |
|-----------|------|----------|
| 主窗口关了就收不到提醒 | 轮询最初放在 App（主窗口）组件里 | 挪到常驻的 WidgetPage |
| 双窗口同时轮询互吃通知 | 队列读完即清空，存在竞争 | 职责分离：Tauri 下只由小组件轮询，主窗口跳过；浏览器下无小组件，App 轮询 |
| tsc 报 `Cannot find name 'notifyNative'` | 重构过程中 App.tsx 残留调用 | 移除残留，notifyNative 独立成 notify.ts |

## 7. 验证记录
- `pnpm --filter desktop build` → 0 错误 ✅
- `pnpm tauri build` → release exe + MSI/NSIS 安装包产出 ✅
- 实测：建一条 1 分钟后到期的任务 → 通知中心收到「⏰ Remainder 任务到期」（待用户确认）
