# M27 发布/同步（K4）

> 方案：`docs/research/团队知识共享平台方案v3-团队模式.md` §2.3 + §9（单节点软隔离定稿）。
> 核心：**发布 ≠ 复制**。发布 = 给目标团队可见权 + 进对方收件箱；对方三选：仅查看 / 同步副本（fork）/ 忽略。

## 实现

### 服务端

- **v15 迁移**（`db/schema.ts`）：
  - `publications`（item_id FK 级联 / from_team / to_team / from_author / source_updated_at / status: pending|viewed|synced|ignored / synced_item_id / resolved_by / published_at / resolved_at）
  - `knowledge_items` 加 `upstream_id` / `upstream_team` / `upstream_updated_at`（fork 副本的上游指针）
- **`routes/publications.ts`**：
  - `POST /api/knowledge/:id/publish {to_team}`：须同时是源/目标团队成员；同条目对同团队只允许一条 pending；发布即通知目标团队其他成员（P0）
  - `GET /api/publications?team=` 收件箱（pending 优先）+ `GET /api/publications/count?team=` 角标
  - `GET /api/publications/:id/item`：**仅查看**——发布即授予可见权，收件方成员无需源团队身份即可读全文；上游已删返回 410
  - `POST /:id/ignore`（已同步不可忽略）
  - `POST /:id/sync`：fork 副本入目标团队（记 upstream_id/upstream_team/upstream_updated_at，related 回指源条目）
  - `POST /api/knowledge/:id/pull`：副本一键拉新（标题/正文/标签/频道/TTL 对齐上游）；**红线：上游删除 → 410，副本保留不回删**
- **更新检测**：LIST_COLS 加派生列 `upstream_has_update`（上游 updated_at > 副本 upstream_updated_at），列表查询零额外请求

### 桌面端

- **二级菜单加「📥 收件箱」**（带未处理数红色角标）
- **`InboxPanel`**（TeamsPage 内）：发布卡片（类型徽章/标题/来源团队/作者/状态）+ 三选按钮；仅查看开只读弹窗（可直接在里面转同步）
- **详情侧栏**：底栏加「📤 发布」→ 弹窗选目标团队（排除本团队）；同步副本显示「⇄ 拉取上游」按钮（无更新时置灰）
- **条目卡片**：上游有更新 → 琥珀色「↻ 有新版本」徽章；无更新副本显示 ⇄ 小标

## 报错及解决方案

| 报错 | 原因 | 解决 |
|---|---|---|
| e2e 假阳性：发布弹窗关了但 publications 表为空 | puppeteer `clickByText('button', ...)` 按 DOM 序匹配到遮罩下团队列表的同名按钮，点击落在遮罩上触发了 onClose | 弹窗内点击必须限定选择器（`div.fixed.z-50 button`）；教训已记入 AGENTS.md |
| TS1002 Unterminated string literal（LIST_COLS） | StrReplaceFile 把多行文本插进了单引号字符串 | 改字符串拼接；SQL 派生列长串用 `+` 连 |
| schema v15 函数体没插入但调用点已加 | StrReplaceFile 批量编辑时 old 串没匹配上（少带反引号闭合），静默跳过 | 批量编辑后用 Grep 验证每处都落实 |
