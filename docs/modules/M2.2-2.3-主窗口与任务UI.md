# M2.2 主窗口布局 + M2.3 任务管理 UI

## 1. 任务背景
M1 后端 API 齐备。本功能点实现主窗口：PRD 3.2 节的三栏布局（左导航 / 中间列表 / 右侧详情）与全部任务页的四型 CRUD。Tauri 壳因机器缺 VS Build Tools 暂不可用（见下），故先在浏览器环境开发验证——React 代码与 Tauri/Web 完全同源。

## 2. 目标
- 左导航【今日|日历|全部任务|跟进|Inbox|文档|设置】可切换，未开发页显示占位
- 全部任务页：四型分组列表 + 新建（含 follow 附加字段）+ 右侧详情编辑 + 完成/删除
- `pnpm build` 类型检查通过

## 3. 需求
- 列表按主线/支线/跟进/想法分组，显示类型徽章、ddl、优先级、完成勾选
- 新建：标题回车即建；选"跟进"时出现被催人+下次跟进日必填项
- 详情：标题/状态/优先级/ ddl /里程碑（仅主线）/标签/备注可编辑保存；完成、删除（带确认）
- 后端不可达时页面显示错误条而非白屏

## 4. 产出
- `desktop/src/api/client.ts`：API 封装 + 全部 TS 类型（Task/TodayView/InboxItem/TaskInput）+ 中文标签映射
- `desktop/src/App.tsx`：三栏布局 + 导航切换（手搓轻量路由，不引 react-router）
- `desktop/src/pages/PlaceholderPage.tsx`：未开发模块占位页（标注对应模块号）
- `desktop/src/pages/TasksPage.tsx`：任务管理完整 UI（列表/新建/详情编辑/完成/删除）
- `desktop/src/vite-env.d.ts`：Vite 类型声明

## 5. 实现方案
- 无路由库：App 内 nav state + 条件渲染（7 个页面，KISS）
- TasksPage 三态数据流：`reload()` 拉全量 → useMemo 按 type 分组 → selectedId 联动右侧详情；详情用 `key={selected.id}` 强制重置草稿态
- API 层统一 fetch 封装，错误抽 `error` 字段抛出；`VITE_API_BASE` 环境变量切换后端地址（M7 Web 端复用点）

## 6. 遇到的报错及解决方案
| 报错/问题 | 原因 | 解决方案 |
|-----------|------|----------|
| `error TS2339: Property 'env' does not exist on type 'ImportMeta'` | 缺 vite/client 类型声明 | 新增 `src/vite-env.d.ts` 写入 `/// <reference types="vite/client" />` |
| `tauri dev` 链接失败 `link: extra operand ...` | ① PATH 中 Git 自带的 GNU link.exe 冒充 MSVC 链接器 ② 机器未安装任何 VS Build Tools | 查 `where link` 确认为 GNU 冒充；用户选择安装 VS Build Tools；winget 后台安装因非交互会话无法弹 UAC 失败（exit 5008），改为用户手动在管理员终端执行安装命令 |
