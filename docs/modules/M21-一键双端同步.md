# M21 一键双端同步（应用内同步按钮）

## 1. 任务背景

系统无账号体系，靠 `data-sync.mjs`（git + 私有仓库，last-write-wins）做 Win/Mac 双端同步，
但需要退出应用、开终端敲命令，链路重。本模块在主窗口侧栏标题旁加一个同步按钮，
点一下完成"提交本地 → 拉远端"全流程，应用运行中即可用。

## 2. 目标

1. 主窗口左上角标题旁有同步按钮，点击完成 commit + push + fetch
2. 远端有新数据时安全应用：SQLite 数据库不能在运行中被换文件，需自动重启后端
3. 分叉（两端都改过）时本地改动不丢：备份推送到远端 backup 分支
4. 断网/未绑定仓库等异常有明确提示，不影响本地使用

## 3. 需求

- 输入：无参数，点击即触发
- 输出与状态：
  - `pushed`：本地领先或无分叉，已推送，提示"另一台设备点同步即可接收"
  - `uptodate`：双端一致
  - `restarting`：远端有新数据，后端自重启应用远端数据，前端轮询健康检查后整体刷新
  - 400 未绑定仓库 / 409 同步进行中 / 502 网络异常（本地改动已提交不丢）
- 边界：syncing 互斥锁防重入；git 操作带超时（fetch/push 90s）

## 4. 产出

- `server/src/routes/sync.ts`：POST /api/sync（新增）
- `server/src/index.ts`：注册 syncRoutes
- `desktop/src/api/client.ts`：`api.sync()`
- `desktop/src/App.tsx`：侧栏标题右侧同步按钮（⟳，旋转动画表示进行中）+ 结果提示文案

## 5. 实现方案

**快速路径（本地领先/一致）**：`wal_checkpoint(TRUNCATE)` → `git add -A` → 有改动则 commit
→ `fetch` → 本地领先则 `push`，全程不动数据库连接，秒回。

**换库路径（远端领先/分叉）**：运行中的 better-sqlite3 持有 db 文件句柄，
直接 `reset --hard` 换文件在 macOS 上连接仍指向旧 inode、Windows 上则被锁。
做法：`POST /api/sync` 返回 `restarting` 后，派生一个脱离父进程的守候脚本
（运行时写入系统临时目录的 `remainder-sync-restart.cjs`，避免污染会被同步的 data 目录），
等 server 进程退出 → `fetch + reset --hard origin/main` → 以原 cwd、原入口
（`process.argv[1]`，保证 dotenv 等相对路径行为一致）重新拉起服务。
前端收到 `restarting` 后轮询 `/api/health`，恢复即 `location.reload()`。

**分叉保护**：本地 HEAD 先 `push origin HEAD:refs/heads/backup-<ts>` 再切远端，
响应里带 backup 分支名告知用户。

## 6. 遇到的报错及解决方案

| 报错/问题 | 原因 | 解决方案 |
|-----------|------|----------|
| 运行中直接 reset --hard 换库不可行 | better-sqlite3 连接持有文件；mac 换 inode 旧连接不可见新数据，Win 文件被锁 | 守候脚本 + 服务自重启（见实现方案） |
| 重启后 dotenv 配置丢失风险 | `dotenv/config` 从 process.cwd() 读 .env | 守候脚本以原 cwd 重新拉起服务 |
| 无改动时点同步仍产生 commit | 服务运行中 remainder.db-shm/wal 会变化被 add 进去 | 与既有 data-sync.mjs 行为一致，暂不处理（gitignore 只排 server.log），后续可考虑排除 shm/wal |

## 7. 验证记录

e2e 实测（独立 PORT=3211 实例 + 临时私有仓 remainder-sync-test，测完已清理数据目录）：

- 场景1 本地有新数据：POST /api/sync → `{"status":"pushed","committed":true}`，远端收到 sync commit ✅
- 场景2 远端领先：另一克隆仓推新文件后 sync → `{"status":"restarting"}`，服务 3 秒内自重启，
  health 恢复 ok，远端文件落到本地 data 目录 ✅
- 场景3 两端分叉：→ `{"status":"restarting","backup":"backup-<ts>"}`，
  远端存在 backup 分支且含本地改动文件（local-marker.txt），本地切到远端状态 ✅
- `pnpm --filter server build` / `pnpm --filter desktop build`：0 错误 ✅
