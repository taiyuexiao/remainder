# M11.1 服务端网页剪藏管线

## 1. 任务背景

M11「网页剪藏 + 知识库升级」的第一步（计划见用户已批准的 M11 计划）。剪藏内容来源有二：浏览器扩展（M11.2）右键同步选区/整页、微信通道（M11.3）剪贴板 HTML。两者统一打到一个服务端入口，经过「提取正文 → 清洗 → 图片本地化」管线后入「剪藏箱」，之后可一键转知识库文档。图片必须本地化：公众号（mmbiz.qpic.cn）有防盗链，直接引用原 URL 在前端会 403。

## 2. 目标

1. `POST /api/clips` 接收原始 HTML（整页或选区片段），经管线入库 clips 表；
2. 正文白名单清洗（无 script/style/内联事件），图片下载到本地并重写 src，失败占位不阻断入库；
3. 剪藏箱 CRUD + 一键转 documents + 本地图片服务；`pnpm --filter server build` 0 错误，`verify-m11.ps1` 全绿。

## 3. 需求

- clips 表（user_version=3 迁移，幂等）：id/url/title/content_html/excerpt/source(extension|clipboard)/status(inbox|converted)/converted_doc_id/created_at；
- 管线：defuddle/node 提取正文（片段返回 `<body></body>` 空壳需判空 fallback）→ 图片本地化（src 取 `data-src || data-original || src`）→ sanitize-html 白名单 → excerpt 纯文本前 200 字；
- 图片下载：超时 10s + 重试 1 次；mmbiz 等 qpic.cn 域名**不发 Referer**，其他域名带原页 Referer；失败替换为保留 alt 的占位 div；存 `server/data/clip_images/<uuid>.<ext>`；
- 路由：POST/GET/DELETE /api/clips、GET /api/clips/:id（预览）、POST /api/clips/:id/convert（转 documents，重复转 409）、GET /api/clips/images/:file（basename 防路径穿越）；
- Fastify 全局 bodyLimit 调到 50MB（整页 HTML 可达数 MB）。

## 5. 实现方案

### 管线顺序（关键）

```
原始 HTML → Defuddle(html, url) 提取正文
  ├─ 判空：剥掉 <html>/<head>/<body> 标签后为空 → fallback 原始 HTML（片段场景）
  └─ 采纳后统一剥掉文档级标签（防 linkedom 丢内层 body）
→ parseHTML('<div id="clip-root">' + html + '</div>') 遍历 img
  ├─ 真实地址 = data-src || data-original || src（懒加载）
  ├─ 相对路径按原页 URL 补全；data: URI 原样保留；空 src 移除
  ├─ 下载（fetch, AbortController 10s, 失败重试 1 次）→ 写 clip_images/<uuid>.<ext>
  │   ext 判定：content-type → URL 路径后缀 → ?wx_fmt= 参数 → 默认 .jpg
  ├─ 成功：img src 重写为 /api/clips/images/<file>
  └─ 失败：replaceWith 占位 div（保留 alt）
→ sanitize-html 白名单清洗
  ├─ allowedTags: p/h1-h3/ul/ol/li/blockquote/pre/code/img/a/table 系/strong/em/br/hr/figure/figcaption 等
  ├─ img 只留 src/alt；a 留 href/target/rel（transformTags 统一注入 target=_blank rel=noopener）
  └─ 不允许任何 style/script/内联事件
→ excerpt：再 parse 一次取 textContent，压缩空白后截 200 字
```

必须在 sanitize **之前**做图片地址提取，否则白名单会把 data-src 剥掉、懒加载图全丢。

### 防盗链

`refererFor()`：`mmbiz.qpic.cn` 等 qpic.cn 域名不设置 Referer 头（公众号 CDN 见 Referer 即 403），其他域名带原页 URL 作 Referer（知乎/CSDN 需要）。

### 路由细节

- 列表 SELECT 不带 content_html（轻行），预览走 GET /api/clips/:id；
- convert：documents 行 content = clip 的 content_html，clip 回填 status/converted_doc_id，重复转换 409；
- 图片服务：`basename(file)` 校验防穿越，按扩展名给 Content-Type，Cache-Control immutable。

## 6. 遇到的报错及解决方案

| 报错/问题 | 原因 | 解决方案 |
|-----------|------|----------|
| 片段剪藏入库后 content_html 为空 | Defuddle 对选区片段返回 `"<body></body>"` 空壳通过了非空判断；且 linkedom `parseHTML('<body>…</body>')` 会丢弃内层 body 标签使内容丢失 | ① defuddle 结果剥掉文档级标签后再判空，空则 fallback 原始 HTML；② 包裹容器改用 `<div id="clip-root">`；③ 入库前统一剥掉 html/head/body 标签 |
| a 标签的 target/rel 清洗后丢失 | sanitize-html 先 transformTags 再过滤 allowedAttributes，`a: ['href']` 把注入的 target/rel 又删了 | allowedAttributes.a 放行 href/target/rel |
| 验证脚本 GET 图片 404 | 脚本正则 `[0-9a-f.-]+` 把扩展名当 hex 截断（jpg 的 j/p 非 hex），匹配出尾点文件名 | 改为显式扩展名分组 `([0-9a-f-]+\.(?:jpg|…))` |
| 验证脚本 GET 图片连接被强制关闭 | PS 5.1 的 Invoke-WebRequest 对 chunked 流式响应有兼容问题（curl/HttpWebRequest 均正常） | 图片断言改用 curl.exe |
