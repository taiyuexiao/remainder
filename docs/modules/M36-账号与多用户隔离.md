# 模块：账号与多用户隔离

> 状态：🚧 开发中
> 最近更新：2026-09-26

## 摘要
为 Remainder 增加真正的账号体系。首个管理员为 `spl`，后续用户通过管理员创建或邀请码注册；任务、文档、剪藏、报告、AI 会话和设置都必须归属账号/空间。

## 动机
当前系统只有 `TEAM_TOKEN`、`x-team-token` 和前端 localStorage 用户名，无法安全区分用户，也无法支持新设备登录后恢复数据。

## 范围与非范围
- 范围内：用户名/密码注册登录、Argon2id、access/refresh token、首个管理员种子、用户空间隔离、邀请码、API Key。
- 明确不做：邮箱验证、找回密码、OAuth、开放自助注册、端到端加密；这些先记录待办。

## 上下游依赖
- 上游：PostgreSQL、服务端 secret 配置、HTTPS。
- 下游：所有 server 路由、desktop 登录态、MCP API Key、团队空间。

## 关键接口与运行时信息
- 关键文件：`server/src/auth/`、`server/src/routes/auth.ts`、`server/src/db/schema.ts`、`desktop/src/api/client.ts`。
- API：`POST /api/auth/register`、`POST /api/auth/login`、`POST /api/auth/refresh`、`POST /api/auth/logout`、`GET /api/auth/me`。
- 表：`users`、`auth_sessions`、`invites`、`api_keys`、`spaces`、`space_members`。
- token：短期 access token + 可撤销 refresh token；请求头使用 `Authorization: Bearer`。
- 验证：用独立临时账号创建/登录/越权访问/退出撤销四类 e2e；不使用真实 `spl` 账号做写测试。

## 设计决策与假设
- 密码使用 Argon2id，不保存明文；`spl` 密码只在初始化 secret 中使用。
- `spl` 为 owner/admin，首次登录不强制改密；后续账号由管理员创建或邀请码注册。
- 用户名和邮箱都可登录；用户名 `spl` 保留给首个管理员。
- 旧 `TEAM_TOKEN` 只作为迁移期兼容开关，云端 API/MCP 不能依赖全局共享 token。

## Bug 与问题记录
### BUG-001 refresh token 轮换后旧 token 未撤销（2026-09-26，已解决）
- 错误行为：WHEN 使用旧 refresh token 再次刷新 THEN 系统仍允许生成新登录。
- 期望行为：WHEN refresh token 被轮换 THEN 系统 SHALL 立即撤销旧 token。
- 不可破坏的行为：WHEN 新 refresh token 有效 THEN 系统 SHALL CONTINUE TO 正常续期。
- 根因：SQL 中 session `id` 被 `users.*` 的 `id` 覆盖。
- 解决方式：session id 别名为 `session_id` 并按该主键撤销。
- 验证方式：`node server/verify-m36.mjs` 验证旧 token 返回 401。

## 报错及解决方案

| 报错/问题 | 原因 | 解决方案 |
|---|---|---|
| pnpm 构建前自动安装报 `ERR_PNPM_IGNORED_BUILDS` | `pnpm-workspace.yaml` 的 `allowBuilds` 值是占位字符串，不是布尔值 | 改为 `better-sqlite3: true`、`esbuild: true` 并重跑 `pnpm install` |
| refresh 后旧 token 仍可再次刷新 | `SELECT s.id, u.*` 两组 `id` 重名，撤销语句实际按用户 id 更新 session | 将 session id 别名为 `session_id`，按 session 主键撤销 |
| v18 数据库迁移时 space 外键失败 | `spaces.owner_user_id` 引用 `users`，但旧库尚未创建 `u_spl` | v19 先创建 pending owner，bootstrap 时只替换 password hash |
