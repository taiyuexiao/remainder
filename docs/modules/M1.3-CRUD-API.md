# M1.3 任务/跟进/Inbox/设置 CRUD REST API

## 1. 任务背景
M1.1/M1.2 已打通 SQLite 连接与建表。本功能点实现 TECH.md 第 5 节的核心 API（documents 与 report/llm 路由留待 M6/M8），是桌面端与 Web 端的唯一数据入口（API 优先原则）。

## 2. 目标
- 任务 CRUD + 完成 + 类型/状态/日期过滤 + 今日视图聚合接口
- 跟进：一键再催（urge_count+1）、改被催人/跟进日
- Inbox：速记增删查 + 一键转任务（回填 converted_task_id，防重复转换）
- settings：key-value 读写

## 3. 需求
- `GET/POST /api/tasks`、`PATCH/DELETE /api/tasks/:id`、`POST /api/tasks/:id/done`
- `GET /api/tasks/today` → `{overdue, today, followUps}` 三段聚合（桌面小组件数据源）
- follow 型任务创建/转换时强制要求 person + nextFollowDate（400 校验）
- `POST /api/follow-ups/:taskId/urge`、`PATCH /api/follow-ups/:taskId`
- `GET/POST/DELETE /api/inbox`、`POST /api/inbox/:id/convert`
- `GET /api/settings`、`PUT /api/settings/:key`
- 删除任务级联删 follow_ups（依赖外键 ON）

## 4. 产出
- `server/src/routes/helpers.ts`（uuid/now/localDate）
- `server/src/routes/tasks.ts`（列表/今日视图/新建/更新/完成/删除）
- `server/src/routes/followUps.ts`、`inbox.ts`、`settings.ts`
- `server/src/index.ts`：注册 4 组路由 + 兜底 Content-Type 解析器
- `server/verify-m13.ps1`：12 步全链路验证脚本（留作回归用）

## 5. 实现方案
- 日期语义：ddl 存 ISO 字符串，按 `substr(ddl,1,10)` 与本地日期（localDate()，非 UTC）比较，避免时区导致的"今天"错位
- 今日视图一次查询三段：active 且 ddl<今天=逾期；ddl=今天=今日；follow 且 next_follow_date<=今天=待跟进（JOIN follow_ups 带出 person/urge_count）
- follow 附加字段与任务同事务语义：POST/PATCH tasks 时同步 upsert follow_ups（ON CONFLICT）
- Fastify 插件式路由（`export default async function`），index.ts 统一 register

## 6. 遇到的报错及解决方案
| 报错/问题 | 原因 | 解决方案 |
|-----------|------|----------|
| 验证脚本 PowerShell 解析失败（中文变乱码、引号断裂） | Windows PowerShell 5.1 对无 BOM 的 UTF-8 .ps1 按 ANSI 读取 | 验证脚本改用纯 ASCII 内容（业务代码不受影响） |
| POST 无 body 报 `415 FST_ERR_CTP_INVALID_MEDIA_TYPE` | Fastify 5 对无 Content-Type 的 POST 无可用解析器（React fetch 无 body POST 同样会踩） | index.ts 注册 `addContentTypeParser('*')` 兜底：空 body→undefined，非空尝试 JSON.parse |
