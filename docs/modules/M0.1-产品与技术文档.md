# M0.1 产品/技术/模板三份基础文档

## 1. 任务背景
用户要求 SDD（文档规范驱动开发）模式：开发前先确定产品形态，编写产品文档与技术文档，后续每个功能点都要有规范文档。本功能点是整个项目的文档地基。

## 2. 目标
- 产出 PRD.md：固化经 grilling 流程确认的产品形态与分期
- 产出 TECH.md：固化架构、选型、数据模型、API、暂存项与风险对策
- 产出 TEMPLATE.md：功能点文档模板，供后续所有 Mx.y 使用

## 3. 需求
- PRD 覆盖：背景痛点、产品形态（桌面小组件/主窗口/速记窗/Web端/桌宠）、任务四型、分期功能清单、非目标、提醒策略
- TECH 覆盖：架构图、选型理由、monorepo 结构、SQLite DDL、REST API、Tauri/定时器/邮件/LLM 实现要点、暂存项（云部署/同步/飞书全量/Live2D）、风险对策
- 模板六节：任务背景/目标/需求/产出/实现方案/遇到的报错及解决方案（另加验证记录）

## 4. 产出
- `docs/PRD.md`（5.3KB）
- `docs/TECH.md`（9.8KB）
- `docs/TEMPLATE.md`（1.0KB）

## 5. 实现方案
内容来源：三轮 grilling 与用户达成的共识 + 三个后台调研代理的报告（桌面任务产品大盘 / 速记-编辑器-LLM-163SMTP / 桌宠技术方案）。关键决策：后端不绑 Supabase，自建 Fastify+SQLite 可任意部署；桌宠走 2D 精灵图路线规避 Live2D license 红线。
