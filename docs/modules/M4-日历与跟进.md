# M4 日历视图与跟进系统

## 1. 任务背景
M2 已让「全部任务」页可用。M4 实现 PRD 第 3.2 节的另外两块：时间序列可视化的月历视图（核心痛点里的"任务时间安排分析"需要直观展示）与 Waiting For 跟进列表（产品差异化点）。

## 2. 目标
- 月历页：月格子显示任务分布、今日高亮、逾期红点、上下月翻页
- 跟进页：列出所有 follow 型任务，按下次跟进日排序，支持改日期、一键再催、标记完成

## 3. 需求
- 月历 6 行 x 7 列，周一起始，跨月日期置灰
- 每个日期格显示最多 3 条任务色块（类型色），超出显示 "+N"
- 跟进页字段：标题、被催人、下次跟进日期（可直接修改）、已催次数、一键再催按钮
- 跟进列表只查 follow 类型，按下次跟进日升序；逾期的卡片红边框

## 4. 产出
- `desktop/src/pages/CalendarPage.tsx`：月历组件
- `desktop/src/pages/FollowUpsPage.tsx`：跟进列表
- `desktop/src/App.tsx`：calendar / follow 两个导航接入真实页面
- `server/src/routes/tasks.ts`：列表接口 `LEFT JOIN follow_ups`，使任务对象附带 person/next_follow_date/urge_count/last_urged_at

## 5. 实现方案
- 月历数据：先拉全量任务（本地个人场景量级可控），按 `ddl.slice(0,10)` 分桶渲染；点击任务只是 title 提示，不实现弹窗（保持 M4 范围）
- 跟进排序：客户端按 `next_follow_date` 升序；批量排序更灵活，不增加后端参数
- API 改造：列表接口统一 LEFT JOIN，所有任务视图都能拿到 follow 元信息，零额外请求

## 6. 遇到的报错及解决方案
| 报错/问题 | 原因 | 解决方案 |
|-----------|------|----------|
| `Property 'next_follow_date' does not exist on type 'Task'` | Task 类型没声明跟进字段 | 在 `client.ts` 的 Task 接口直接加可选的 person/next_follow_date/urge_count/last_urged_at；清空 FollowTask 扩展 |
| `Cannot find name 'TaskStatus'` | FollowUpsPage 没导入类型 | 补上 `type TaskStatus` 导入 |
