# M17 时间轴全景视图 · 调研与产品设计

## 1. 需求本质

现有模块的盲区：**今日**只看今天、**全部任务**是 ddl 列表、**日历**是月历点阵——都回答不了「我现在同时背着几件事？未来两周哪里会撞车？哪些项目一直在拖？」这类**时间维度全景**问题。

用户明确要求：不要机械排列的时间轴，要有设计感的可视化。

## 2. 调研

### 2.1 开源组件库（GitHub 实查）

| 库 | License | 维护 | 特点 | 适配度 |
|---|---|---|---|---|
| **SVAR React Gantt** | MIT | 活跃（React 19，10k 任务级性能） | 任务条+进度+拖拽改期+缩放+虚拟化 | ⭐⭐⭐⭐ |
| **gantt-task-react**（MaTeMaTuK 系 forks） | MIT | 原版停更，fork 续命 | 经典 React 甘特，条/里程碑/进度/拖拽 | ⭐⭐⭐ |
| **Frappe Gantt** | MIT | 活跃 | 纯 SVG 轻量、颜值高、无 React 封装 | ⭐⭐⭐ |
| **vis-timeline**（vis.js） | MIT/Apache | 活跃 | 泳道分组+区间条+缩放，非甘特向 | ⭐⭐⭐⭐ |
| DHTMLX / Syncfusion 甘特 | 商用为主 | — | 企业级（依赖/关键路径），过重 | ⭐ |

**结论**：这些都是"项目管理甘特"，自带依赖箭头/关键路径等我们用不上的重量。Remainder 的需求是**个人任务全景图**，更轻、更偏设计感。

### 2.2 产品参照

| 产品 | 值得抄的设计 |
|---|---|
| **Notion Timeline** | 条可拖拽改期/拉宽改范围；时间粒度小时→年无极切换；"重叠任务一眼可见" |
| **Linear** | 泳道按项目分组 + 进度环 + 今日竖线 |
| **Toggl Plan** | 每行一条泳道，条上直接显示进度百分比，颜色即状态 |
| **TickTick 甘特** | 逾期任务条自动变红 |
| **Sunsama** | "今日"居中锚定，未来向右展开 |

### 2.3 调研结论

通用模式 = **泳道（项目）× 时间轴（天）+ 进度条 + 今日锚线 + 状态色彩**。我们的差异化：**跟进类项目的"下次该催日期"**和**逾期警告**是一等公民，这在所有通用产品里都没有。

## 3. 产品设计：「全景 Timeline」

### 3.1 布局

```
┌─────────────────────────────────────────────────────────┐
│ [周][月][季]   今天：9-01      ⚠ 逾期 2  ◆ 待跟进 3      │
├──────────────┬──────────────────────────────────────────┤
│ 项目泳道      │  8/26  9/02  9/09  9/16 …（可横向滚动）   │
│              │              │今日                         │
│ NAC架构调研   │ ████████░░░░ 63% │                        │
│ 评测模块开发  │   ██████████ P1  │        ◆9/11 ddl        │
│ 管理工作台    │ ░░░░██████████████▓▓ 进行中               │
│ 流程审批(跟进)│ ──────◆───────◆──│◆  ← 下次跟进菱形标记    │
│ Kimi W 支线   │          ████    │                        │
│ …            │              │                            │
├──────────────┴──────────────────────────────────────────┤
│ 迷你密度热图：▂▃▅█▅▃▂▃▄█▅…（哪天任务堆积一眼可见）          │
└─────────────────────────────────────────────────────────┘
```

### 3.2 视觉编码规则（核心设计）

| 维度 | 编码 |
|---|---|
| **条（bar）** | 项目创建日 → ddl 的时间跨度；填充比例 = 子任务完成度（done/total）；半透明底 + 实心进度 |
| **颜色** | 主线=indigo / 支线=sky / 跟进=amber / 逾期=red（覆盖一切类型色） |
| **今日竖线** | 红色细线贯穿所有泳道 + 顶部"今天"标签 |
| **ddl 标记** | 条右端点 ◆ 菱形 + tooltip 日期 |
| **跟进标记** | 跟进型项目在 nextFollowDate 位置放 ◆（amber），逾期跟进变红脉动 |
| **无 ddl 项目** | 不入图（放底部"未排期"折叠区，可从那里拖入时间轴排期） |
| **密度热图** | 底部一行：每天落在该日的活跃项目数 → 色阶（slate→red），点击某天定位 |

### 3.4 交互

- **缩放**：周（默认，今天居中）/ 月 / 季 三档
- **拖拽改期**：拖条左右移动 = 改项目 ddl（调用现有 PATCH API）
- **hover 卡片**：项目名 / 类型 / 进度 x/y / ddl / 已催次数 / 下次跟进日
- **点击条**：跳转到该项目（全部任务页展开）
- **未排期区**：底部抽屉，拖入即排期

### 3.4 技术方案

**自研 SVG/React 组件**（`desktop/src/pages/TimelinePage.tsx`），不用甘特库：
- 我们的数据模型（项目 + ddl + 进度 + 跟进日）和交互需求（热图、未排期区）与通用甘特库匹配度低，库的反成包袱
- 项目已有自研 canvas/SVG 经验（画布、桌宠），风格统一
- 复杂度可控：泳道 + 条 + 标尺 + 热图 ≈ 450 行
- 数据全部走现有 API（`api.projects.list()` 已含 done_count/total_count/person/next_follow_date）
- 入口：左侧导航加「🗺 全景」，放在「日历」之后

### 3.5 形态（用户反馈后修订）

- **页内全景**：导航页即全景图（中等密度）
- **⛶ 全景模式**：右上角按钮 → 全屏弹窗（fixed inset-0），更大行高/日宽/字号，沉浸查看；Esc 或 ✕ 关闭
- 同一 `TimelineChart` 组件两形态复用（`density: 'page' | 'fullscreen'` prop）

### 3.6 视觉品质红线（用户反馈后新增）

> “好看不是花里胡哨，而是该有的内容都有、组件和谐、不生硬、不一眼糊弄事”

- 泳道奇偶行 2% 明度差（#fff / #f8fafc），不用生硬的实线分隔
- 条：圆角 999、半透明底色 + 实心进度段、投影极浅；类型色取 tailwind 400 档（不刺眼）
- 周末列 3% 灰底；月初加分隔线 + 月标签；今日线 1.5px 红 + 顶部「今天」胶囊
- hover 卡片为自绘浮层（不用浏览器 title）：项目名/类型徽标/进度环/ddl/已催 N 次/下次跟进
- 逾期条：red-400 实心 + 末端 ⚠；完成的项目：emerald-300 细条收编
- 密度热图：圆角小格 4px 间距，slate-100 → rose-500 五档，点击平滑滚动定位
- 未排期区：底部虚线框抽屉，chips 圆角全角

### 3.5 分期

- **v1（本次）**：泳道全景 + 进度条 + 今日线 + ddl/跟进标记 + 热图 + 周/月缩放 + hover 卡片
- **v1.1**：拖拽改期、未排期拖入
- **v2 backlog**：点击跳项目、与日历页联动、LLM 负载分析（"未来两周哪天最挤"）

## 4. 验证标准

1. 12+ 个项目同时入图不卡（SVG 元素 < 500）
2. 逾期项目条变红、今日线位置正确（e2e 断言）
3. 热图数值与 API 数据一致
4. build 0 错误
