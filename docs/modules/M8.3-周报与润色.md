# M8.3 周报生成 + LLM 润色

## 1. 任务背景
PRD v2 的智能文档能力补齐：用户周报是给领导看的正式材料，手写耗时。本期做两件事：一键从任务/项目数据生成周报文档；编辑器内文本润色。LLM 用 DeepSeek（OpenAI 兼容，可配置）。

## 2. 目标
- `POST /api/llm/weekly-report`：聚合本周数据 → LLM 生成周报 → 落 documents（Tiptap JSON，可继续编辑）
- `POST /api/llm/polish`：文本润色
- 未配置 LLM key 时：周报**降级为模板数据版**（照样建文档），润色返回 503 明确提示
- 文档页工具栏加「生成周报」「润色」按钮

## 3. 需求
- 周报聚合：本周完成的项目/子任务、进行中项目（带进度 x/y）、逾期任务、跟进项目（被催人/已催次数/下次跟进日）
- LLM prompt 限定：只能基于给定数据、不编造；固定小节结构
- 生成的周报是 Tiptap JSON（##/列表/段落由 mdToTiptapJson 转换），不是纯文本

## 4. 产出
- `server/src/llm/index.ts`：`chat()` 通用调用 + `generateWeeklyReport(WeeklyData)` + `polishText(text, instruction?)` + WeeklyData 类型
- `server/src/routes/llm.ts`：两个端点 + 本周数据聚合 + mdToTiptapJson + buildFallbackReport（无 LLM 降级模板）
- `server/src/index.ts`：注册 llmRoutes
- `desktop/src/pages/DocsPage.tsx`：工具栏「📊 生成周报」「✨ 润色」（选中则润色选区，否则全文）
- `desktop/src/api/client.ts`：api.generateWeeklyReport / polishText
- `server/verify-m83.ps1`：验证脚本

## 5. 实现方案
LLM 不可用的降级策略：周报是数据驱动场景，没 LLM 就用模板把数据按小节拼出来，用户拿到手改改也能用——而不是报错挡住了事。前端润色拿到结果后直接替换编辑器内容。

## 6. 遇到的报错及解决方案
| 报错/问题 | 原因 | 解决方案 |
|-----------|------|----------|
| 验证脚本 weekly-report 断言 code 为空 | 脚本的 curl ApiRaw 用 `-w '\n%{http_code}'`，PS5.1 数组 splat 传参对特殊字符处理不稳；大响应体下解析失败 | weekly-report 改用 Invoke-RestMethod 断言；curl 只留小响应的 polish |
| 中文断言失败（title/tags 含"周报"） | 双层编码坑：ps1 文件被 PS5.1 按 ANSI 读 + Invoke-RestMethod 对无 charset 的 JSON 按 latin-1 解码 | 验证脚本改纯 ASCII；中文比较改为结构断言（tags 长度=2、title 长度>3、content 以 '{' 开头） |
| 子代理两次 401 | 子代理模型凭证故障 | M8.3 由主线程直接完成（后端主体其实已由前次代理写好，本次补降级与验证） |
