# M6 提醒系统后端（定时器 + 邮件日报 + LLM）

## 1. 任务背景
M3/M5 等前端提醒入口被 Tauri 编译阻塞（待装 VS Build Tools），但后端的主动触达逻辑可以独立完成。本功能点实现：到点提醒队列、定时邮件日报、可选 LLM 总结。Windows 系统通知弹窗待 Tauri 可用后由前端轮询 `/api/notifications` 取走触发。

## 2. 目标
- 每分钟扫描一次到期任务，生成待推送通知队列
- 每晚 21:00 自动发送日报邮件（手动触发接口便于调试）
- 邮件中可嵌入 DeepSeek 生成的中文总结

## 3. 需求
- 任务表新增 `reminded_at` 字段，防止同一 ddl 重复提醒
- 通知队列 API：`GET /api/notifications`、`POST /api/notifications/check`（手动触发扫描）、`POST /api/notifications/clear`
- 日报聚合数据与 `/api/tasks/today` 一致：今日已完成 / 逾期待办 / 今日到期待办 / 今日待跟进
- 邮件通过 163 SMTP 发送，HTML 格式
- LLM 总结可开关（`LLM_ENABLED`），失败时邮件中显示失败原因而非阻断发送

## 4. 产出
- `server/src/db/schema.ts`：tasks 表新增 `reminded_at TEXT`
- `server/src/mailer.ts`：163 SMTP 发送封装
- `server/src/llm/index.ts`：DeepSeek 日报总结生成
- `server/src/scheduler/index.ts`：每分钟扫描提醒 + 日报定时发送
- `server/src/routes/report.ts`：`POST /api/report/daily/send` 手动触发
- `server/src/routes/notifications.ts`：通知队列 API
- `server/src/index.ts`：注册路由、启动 scheduler

## 5. 实现方案
- 提醒扫描 SQL：`status IN ('todo','doing') AND ddl <= now() AND (reminded_at IS NULL OR reminded_at < ddl)`
- 日报定时：比较当前小时/分钟与 `REPORT_TIME`（默认 21:00），命中且当日未发则发送；用内存变量 `reportSentDate` 去重
- LLM prompt：把四段数据 JSON 喂给 `deepseek-chat`，system 角色限定为程序员口吻、2-4 句话
- 空 body 兼容：index.ts 自定义 `application/json` 解析器，让 `POST /api/notifications/check` 这类无 body 接口不再报 400

## 6. 遇到的报错及解决方案
| 报错/问题 | 原因 | 解决方案 |
|-----------|------|----------|
| `Property 'createTransporter' does not exist` | 手误把 `createTransport` 写成 `createTransporter` | 修正为 nodemailer 正确 API 名 |
| `FST_ERR_CTP_EMPTY_JSON_BODY` | Fastify 默认 JSON parser 拒绝空 body 的 POST | 自定义 application/json parser：空 body → undefined |
| report.ts 中 db.all() 返回 unknown[] 无法传给 li() | better-sqlite3 默认返回 unknown | 加 `TodayRow` 类型断言 |
