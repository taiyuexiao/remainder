# 模块：云端部署与安全

> 状态：🚧 开发中
> 最近更新：2026-09-26

## 摘要
将 Remainder API、前端静态资源、PostgreSQL、对象存储和备份服务部署到腾讯云服务器，提供 HTTPS、账号 secret 管理、备份和恢复流程。

## 动机
本地应用要支持多设备登录和云端同步，必须有一个稳定、可备份、可恢复的服务端。

## 范围与非范围
- 范围内：Docker Compose、Caddy/Nginx HTTPS、PostgreSQL、S3 兼容对象存储、服务端 secret、每日备份、健康检查。
- 明确不做：端到端加密、Serverless、多云容灾；管理员可恢复服务端数据。

## 上下游依赖
- 上游：腾讯云 Linux 服务器、域名/DNS、对象存储凭据、SMTP（暂缓）。
- 下游：desktop 云端 API、账号模块、同步模块、MCP API Key。

## 关键接口与运行时信息
- 关键文件：`deploy/docker-compose.yml`、`deploy/Caddyfile`、`.env.example`、`server/src/config.ts`。
- 环境变量：`DATABASE_URL`、`S3_ENDPOINT`、`S3_BUCKET`、`S3_ACCESS_KEY_ID`、`S3_SECRET_ACCESS_KEY`、`AUTH_SECRET`、`TEAM_TOKEN`。
- 部署：`docker compose up -d`；健康检查 `/api/health`；备份保留 30 天。
- 服务器目标：腾讯云 Ubuntu，部署地址由环境配置提供；源代码和 secret 不进入 Git。

## 设计决策与假设
- 使用 Docker Compose 单机部署；数据库选 PostgreSQL，附件选 S3 兼容对象存储。
- 使用域名 + Let’s Encrypt HTTPS；纯 IP 只能临时自签证书。
- 服务器密码不写入代码、文档或命令记录；部署改用 SSH Key，完成后轮换密码。
- 管理员可恢复明文服务端数据，因此不承诺端到端隐私。

## 报错及解决方案

| 报错/问题 | 原因 | 解决方案 |
|---|---|---|
| `docker build` 无法连接 Docker daemon | 当前 macOS Docker Desktop 未运行 | Compose 配置校验已通过；构建/部署前启动 Docker Desktop 或在云服务器执行 |
