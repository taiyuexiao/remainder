# M11.4 知识库升级——文档元数据 + FTS5 全文搜索

剪藏链路（M11.1 管线 → M11.2 扩展 → M11.3 微信剪贴板 → M11.5 剪藏箱页）完成后，文档量开始增长，需要知识库能力。用户决策：v1 纯搜索 + 标签 + 来源链接，**不做双链/目录树**。

3. DocsPage 加搜索框/标签编辑/来源链接展示；双端 build 0 错误，verify-m114.ps1 全绿。

## 3. 需求

### 后端
- user_version=4 幂等迁移：documents 加列 source_url/tags/summary/clip_id/content_text；建 `docs_fts`（`fts5(title, content_text, tags, content='documents', content_rowid='rowid', tokenize='trigram')`）；存量回填 content_text + rebuild；

- PATCH /api/documents/:id 支持 tags/source_url/summary；content 变更时重算 content_text；
- clips convert 写入 source_url（clip.url）/summary（clip.excerpt）/clip_id。

### 前端

- 列表项显示：📥 剪藏来源图标、摘要一行截断、标签灰小字、来源域名链接（新窗口）；
- 编辑器标题下方加标签输入（逗号分隔，回车/失焦保存）+ 来源链接。

## 5. 实现方案

### FTS5 选型与同步策略
- **trigram 分词**：CJK 按三字滑窗切词，中文搜索开箱可用； latin 词也行；
- **external content + content_rowid=rowid**：documents.id 是 TEXT uuid，FTS 用 SQLite 自增 rowid 关联，查询 `JOIN documents d ON d.rowid = docs_fts.rowid`；
- **content_text 实列**：external content 的 rebuild 从 documents 表读列，但 documents.content 是 HTML/Tiptap JSON，不能直接索引——故加 content_text 实列由应用层维护（stripToText：JSON 开头则递归收集 text 节点，否则剥 `<[^>]*>`）；
- **同步策略 = 全量 rebuild**：external content 表单行删除必须用携带旧值的 special 'delete' 命令（`INSERT INTO docs_fts(docs_fts,rowid,...) VALUES('delete',...)`），极易踩坑且 SQLite 3.51 有 trigram delete bug（本机 3.53.2 已修）。个人知识库数据量小，任何变更后 `INSERT INTO docs_fts(docs_fts) VALUES('rebuild')` 微秒级完成，绝对一致，KISS。

### 搜索路由
- q≥3：`docs_fts MATCH '"<q 双引号转义>"'`（短语查询），ORDER BY bm25(docs_fts)；FTS 语法异常降级 LIKE；
- q<3：LIKE '%q%' 三列兜底（trigram 无法匹配不足 3 字的串）。

## 6. 遇到的报错及解决方案

| 报错/问题 | 原因 | 解决方案 |
|-----------|------|----------|
| FTS 搜中文命中为空 | PS 5.1 的 Invoke-RestMethod 把字符串 body 按 latin-1 发送，中文入库变 `????` | verify 脚本 Api 函数改用 `[Text.Encoding]::UTF8.GetBytes(ConvertTo-Json …)` + charset=utf-8 |
| external content 单行 delete 语法坑 | 'delete' special command 需携带全部旧列值 | 放弃单行同步，改用全量 rebuild |
