# M11.3 微信通道——剪贴板剪藏

## 1. 任务背景

M11 计划确认的微信通道 v1 方案：微信里无法直接调扩展，用户在公众号文章里**复制片段**（微信复制会带 CF_HTML 富文本格式）→ 按热键 `Ctrl+Alt+Space` 唤起速记窗 → 点「剪贴板剪藏」→ HTML 走 M11.1 管线（source=clipboard）入剪藏箱。复用现有速记窗，不做自动监听。

## 2. 目标

1. Tauri command `read_clipboard_html` 读取剪贴板 HTML（Windows CF_HTML）；
2. 速记窗加「📋 剪贴板剪藏」按钮，一键入剪藏箱并反馈；
3. `cargo build` + `pnpm --filter desktop build` 双绿。

## 3. 需求

- Rust：clipboard-rs 0.3（`Clipboard` trait 的 `get_html()` 读 CF_HTML）；CF_HTML 带 `<!--StartFragment-->`/`<!--EndFragment-->` 标记时只截取 fragment 部分，取不到给全文；空内容返回 None；
- 前端 CapturePage：
  - invoke 调 command → 有内容则 POST /api/clips（source='clipboard'，url 空，title 从 HTML 提取 `<title>` 或纯文本前 50 字）→ 「已剪藏 ✓」600ms 后关窗；
  - 剪贴板无富文本（纯文本）→ 提示「剪贴板无富文本，直接用上面输入框速记」；
  - 非桌面端环境（浏览器）→ 提示需在桌面端使用；
- client.ts 加 `api.createClip`；
- 权限：Tauri 2 的 capabilities/ACL 只管插件与 core 命令，**应用自定义 command 不受 ACL 管控**，`core:default` 已够，无需改 default.json。

## 5. 实现方案

```
微信/浏览器复制图文（CF_HTML 进系统剪贴板）
  → Ctrl+Alt+Space 唤起速记窗（M2 已有）
  → 点「剪贴板剪藏」→ invoke('read_clipboard_html')
  → Rust: ClipboardContext::get_html() → 截取 StartFragment~EndFragment
  → POST /api/clips {html, url:'', title, source:'clipboard'}
  → M11.1 管线（defuddle 提取 + sanitize + 图片本地化，mmbiz 图不发 Referer）
  → 剪藏箱出现条目（M11.5 页面可见）
```

- 标题提取：优先 `<title>`，否则剥标签取纯文本前 50 字；
- 微信片段一般不含 `<title>`，且图片是 mmbiz data-src 懒加载——管线 M11.1 已处理这两件事，前端无需加工 HTML；
- `invoke` 失败（浏览器环境无 Tauri 注入）走 catch 分支提示，不影响速记主流程。
