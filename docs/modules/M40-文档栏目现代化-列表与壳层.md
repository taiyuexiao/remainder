# M40 — 文档栏目现代化：列表排版 / 续号 / 批量缩进 / 颜色入口 / 双击钻取 / 壳层统一

> 日期：2026-10-17 ｜ 状态：已完成（desktop 端，server 无改动）

## 背景

文档栏目经过 M29/M33/M33b 等多轮优化后仍存留「十年前 UI」观感，用户反馈集中在五点：

1. 有序列表序号与正文左缘错位——顶格输入「1. 」转列表后序号向左跳出正文栏（M33b 悬挂缩进方案方向反了：把序号挂得更左、正文还右移 8px）
2. 回车生成「2.」后退格删除标记，之后键盘无路回到列表；工具栏 toggle 只会另起新列表、序号从 1 重来
3. 无法全选多个列表项后按 Tab 集体右移
4. 字体颜色与背景填充共用一个按钮一个二级面板
5. 树/列表页与编辑器是两套设计体系（Tailwind slate+indigo + 系统 emoji + window.prompt/confirm）

## 改动清单

### ① 列表序号顶格（fe.css + listStartSync）

- 放弃原生 `list-style` marker（位置不受 CSS 控制），改用 **CSS counter + `li::before` 绝对定位**：
  - `ol > li::before { content: counter(fe-ol) "."; position: absolute; left: 0 }` → 序号精确钉在正文左缘（与段落 0 偏移）
  - `ol > li { padding-left: 1.6em }` → 正文跟在序号后，长句换行悬挂对齐
  - 无序列表同法（圆点 0 对齐，`padding-left: 1.1em`）；`taskList` 用 `:not([data-type="taskList"])` 排除
- `ol[start]` 兜底：WKWebView 不支持 `counter-reset` 里的 `attr()`，新增 `listStartSync` 扩展用 node decoration 把 `start` 写进 ol 的内联 `style="counter-reset: fe-ol N-1"`（`editor2/listStart.ts`）

### ② 续号（blockInputRules.ts 新增两条输入规则 + 自动合并插件）

- 顶层段落输入 `N. ` + 空格：
  - 上一兄弟是有序列表 → **并入**列表末尾续号（`appendParaToList`）
  - 不紧邻（中间隔着退格出来的段落）→ 新建 `start=N` 的列表（`wrapParaAsOrderedList`，Word/飞书同款「3. 」起号行为）
- 顶层段落输入 `- ` 且上一兄弟是无序列表 → 并入
- 新增 `feAutoJoinLists` appendTransaction 插件：相邻同类列表自动合并（toggle/粘贴产物），编号自然延续

### ③ Tab 批量缩进（indent.ts）

- `indentSelection(editor, dir)`：选区落在同一列表内 → **一次** `sinkListItem`/`liftListItem`（prosemirror 原生支持范围批量：选中第 2、3 项 Tab → 平行挂到第 1 项下）；跨顶层块 → 段落/标题 `indent±1`
- 单光标行为不变（列表内 sink/lift、普通块 indent）；代码块/表格内不处理

### ④ 颜色入口拆分（ToolbarBtns/Toolbar/BubbleToolbar）

- `ColorPanel` 拆为 `FontColorPanel`（A 图标+色条）与 `HighlightPanel`（荧光笔图标+色条），顶部工具栏与选中浮动条各为两个独立按钮
- 按钮下方 3px 色条实时显示当前颜色（`textStyle.color` / `highlight.color`），面板底部「恢复默认」/「清除填充」

### ⑤ 双击钻取（DocsPage.tsx）

- `drillStack` 钻取栈：双击文件夹行 → 中间栏目独占为该文件夹直接子级（`DrilledTree`），头部变「← 返回 + 文件夹名」，可连续下钻、逐级返回
- 右侧 `FolderDetails` 面包屑同步跟随栈顶；删除钻取路径上的文件夹时自动弹栈
- 单击行为改为「仅选中」（原来点击=选中+展开），展开交给行首箭头——与双击钻取语义不冲突

### ⑥ 斜杠菜单照搬飞书（SlashMenu.tsx / fe.css）

- 去掉条目小字描述（`desc` 仍保留在数据里供过滤），行高 40px、图标 20px 无底座、按类型着色（正文类蓝 / 代码块绿 / 分割线橙），圆角 10、悬浮阴影加重

### ⑦ 壳层统一（DocsPage.tsx / App.tsx / components/NavIcons.tsx 新增）

- 全部 emoji 换自绘 SVG 线性图标（`NavIcons.tsx`，24px viewBox / 1.7px 描边，与 editor2/icons 同风格）
- 主色 indigo → 品牌蓝 `var(--brand)`（#3370FF），灰阶迁 `--text-1/2/3`、`--bg-2`、`--border-light` 等 fe token
- `window.prompt`（重命名）→ `InputModal`；`window.confirm`（删文件夹）→ `ConfirmModal`；`alert`（操作失败）→ `.fe-toast` 顶部 toast
- 文档/文件夹行卡片化：图标容器（文件夹蓝底、文档灰底）、hover 行内操作按钮、hover 边框

## 验证

- `pnpm --filter server build` / `pnpm --filter desktop build` 双端 0 错误
- 独立实例 e2e（PORT=3990 + `REMAINDER_DB_PATH=/tmp` 独立空库 + `VITE_API_BASE` 指向测试实例，真实库零接触），无头浏览器实测：
  - 场景 A：顶格「前提问题：」↵「1. 」+空格 → 自动成列表；实测 `ol` 盒与段落左缘偏移 **0px**、序号 `::before` left=0、正文 +25.6px（1.6em）✓
  - 场景 B：回车生成空「2.」→ 退格 lift 出列表 → 续写 → ↵「2. 」+空格 → 新建 `start="2"` 列表且内联 `counter-reset: fe-ol 1`（渲染「2.」）✓
  - 场景 C：退格出列表后（紧邻）直接「2. 」→ 并入原列表（单列表 2 项、无 start、编号连续）✓
  - 场景 D：选中第 2、3 项 Tab → 平行子列表 `[1[2,3]]`（非阶梯）；Shift-Tab 完整退回平级 ✓
  - UI：斜杠菜单飞书式渲染 ✓；两个颜色独立按钮+各自面板 ✓；双击钻取（头部 ← + 独占子级 + 右侧面包屑跟随）✓；重命名弹窗改名生效 ✓；主菜单 SVG 图标 ✓

## 报错及解决方案

| # | 报错 / 现象 | 原因 | 解决 |
|---|---|---|---|
| 1 | M33b 方案下「序号悬出左缘、正文右移 8px」，用户反馈方向反了 | `padding-left:1.4em` + `margin-left:-0.9em` 残差 0.5em；且「正文对齐、序号悬挂」不是用户要的「序号顶格」 | 改为 CSS counter 方案：序号 `left:0` 钉在正文左缘，正文 `padding-left:1.6em` 跟随 |
| 2 | 原生 marker 无法精确顶格（宽度随位数变化） | 浏览器把 outside marker 右对齐贴着内容盒，位置不受控 | 弃用原生 marker（`list-style:none`），`::before` 绝对定位渲染序号 |
| 3 | `ol[start=2]` 渲染成「1.」 | WKWebView 不支持 `counter-reset: fe-ol attr(start integer, 1)` | `listStartSync` 扩展用 node decoration 写内联 `style="counter-reset: fe-ol N-1"`（内联样式覆盖样式表 reset） |
| 4 | Tab 多选缩进产生阶梯嵌套（1[2[3]]）而非平行 | 初版逐项独立 sink（倒序循环），每项各自成为前一项的子项 | 改为对选区直接调一次 `sinkListItem`/`liftListItem`——prosemirror 原生按 blockRange 批量处理，结果为平行子列表 |
| 5 | 测试环境真实双击不触发（Playwright `dblclick` 只有 click+dblclick、无第二次 click） | 合成/CDP 双击事件序列与真实浏览器（两次 click）不同 | 设计稿阶段改为「click 计时 + 原生 dblclick 双路径去重」；生产 React 树 DOM 稳定，直接 `onDoubleClick` 即可（实测通过） |
| 6 | 无头浏览器里 Playwright locator `click()` 全部超时、Space/Enter 键被内核吞掉 | IAB 内核对部分真实输入事件命中测试异常 | 测试钩子：React fiber 链取 editor 实例，`view.someProp('handleTextInput')` 模拟键入（输入规则照常触发），结构键用合成 `keydown`；纯 UI 点击用 `evaluate` DOM click |
| 7 | `start="2"` 的列表在 Shift-Tab/退格链路后编号错乱风险 | CSS counter 不感知 `start` | 合并/拆分均走 ProseMirror 结构操作；start 由节点属性驱动 decoration，结构变化后自动重算 |
| 8 | 重命名后校验 `aside` 文本找不到新名字 | 文档页有两个 aside（App 主导航 + DocsPage 树），`querySelector('aside')` 命中前者 | 测试脚本用 `querySelectorAll('aside')[1]`；生产代码无影响 |

## 已知边界

- 顶层列表**全选**（含首项）按 Tab 无效果——首项没有可挂的前兄弟，与 ProseMirror/Notion 标准行为一致；选中第 2 项起的部分才可右移
- 相邻同类列表自动合并是全局行为（对齐飞书）；若刻意需要两个紧邻的同类型列表（极罕见），当前会被合并
- 快速应用「上次使用的颜色」（点按钮直接套色、点箭头才开面板）未实现，当前两按钮均为点击开面板，列为后续优化
