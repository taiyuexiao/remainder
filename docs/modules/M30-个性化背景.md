## 实现

### server（`routes/assets.ts`）

- `POST /api/assets/background`：multipart 上传（png/jpg/webp/gif），存 `server/data/assets/bg-<ts>.<ext>`，settings 表 `bg_image` 记文件名；换新自动删旧
- `GET /api/assets/background`：读当前背景图（404=未设置）
- `DELETE /api/assets/background`：删除并清设置

### desktop

- **`components/BackgroundLayer.tsx`**：App 根部 fixed 底图（z-0），`bg-config`（localStorage：enabled/opacity/blur/fit/ts）+ `bg-config-changed` 事件热应用；毛玻璃带 1.05 放大边缘补偿
- **可读性设计**：背景启用时 `body.app-has-bg` → 导航栏/页面壳层降半透（0.82 + backdrop-blur），**内层卡片保持不透明**（业界红线：文本对比度优先）
- **设置页「🎨 个性化背景」区**：上传/更换/停用/清除 + 透明度滑杆（5~60%，默认 15%）+ 毛玻璃滑杆（0~20px）+ 填充模式（cover/contain/fill），全部实时生效
- `client.ts`：`uploadBackground`（multipart 带 token 头）/ `deleteBackground`

## P1.2 z-order 遮挡修复（用户反馈：设置页全被盖/剪藏半盖/文档组件遮挡）

- **根因**：背景层 `absolute + z-index: 0` 是定位元素，按 CSS 绘制次序会画在**非定位的 `<main>` 内容之上**——设置/剪藏等页内容被整个盖住；侧边栏因有 backdrop-filter 意外幸存
- **修复**：背景层 `z-index: -1` 沉底（壳层透明规则不变）；壳层不透明度 0.78→0.85；**文档编辑器例外实心白**（PyCharm 式：编辑区永不透图）
- **「文本加粗能否解决可读性」的结论**（答用户问）：不能。字重不改变对比度（WCAG），PyCharm 的秘诀是编辑区实心 + 图只露在边框留白——我们同方案
- e2e：elementFromPoint 断言内容元素在最顶层（设置页/文档工具栏），编辑器底色 rgb(255,255,255)

## P1.1 scrim 模型修正（用户实测「文本看不清」后返工）

> 调研：`docs/research/个性化主题方案调研.md` §5（scrim/Muzei/iOS 方案对比）。
> 修正：**图不被压淡（永远 100%）**，图与内容之间加 scrim 遮罩层（白纱布 85% 默认 / 黑纱布可切深色图）。

- `BgConfig` 重构：opacity 语义废弃 → `scrim`（60~95%）+ `scrimDark` + `dim`（0~60% 变暗）+ `grey`（0~100% 灰度）+ blur；旧配置 opacity 自动折算 scrim=1-opacity
- BackgroundLayer 两层：img（filters: blur/brightness/grayscale 作用于图本身）→ scrim div（rgba 白/黑 × 浓度）
- 设置页旋钮换语义：遮罩浓度 / 遮罩颜色（白纱布·黑纱布）/ 图片变暗 / 图片灰度 / 毛玻璃 / 填充模式
- e2e 六断言全绿（图 100%+scrim 85%、浓度滑杆、dim/grey 滤镜、黑纱布切换、任务页可读性截图）
