# M1.1 Fastify + SQLite 连接 + 配置管理

## 1. 任务背景
M0.2 脚手架已让 Fastify 空壳与配置加载跑通。按计划 M1 是后端基础，第一步要把 SQLite 真正接进来——它是全应用唯一数据源（TECH.md 第 1 节"API 优先、SQLite 本地即真理"）。

## 2. 目标
- 服务启动时自动创建 `server/data/remainder.db` 并建立连接
- `/api/health` 返回数据库连通状态（`db: up`）

## 3. 需求
- better-sqlite3 同步驱动；WAL 模式；外键约束开启
- data 目录自动创建；db 文件不入 git（.gitignore 已覆盖）
- 配置仍走 .env（M0.2 已实现的 config.ts 不变）

## 4. 产出
- `server/src/db/connection.ts`：Database 单例（WAL + foreign_keys + 自动建目录，导出 DB_PATH）
- `server/src/index.ts`：/api/health 增加 `db` 与 `dbPath` 字段（SELECT 1 探活）

## 5. 实现方案
`connection.ts` 用 `fileURLToPath` 定位包根下的 `data/`，`mkdirSync(recursive)` 兜底；导出单例供 routes/scheduler 共用。health 接口执行 `SELECT 1` 作为 db 探活，一次调用同时验证进程与数据库。

## 6. 遇到的报错及解决方案
| 报错/问题 | 原因 | 解决方案 |
|-----------|------|----------|
| `Could not locate the bindings file`（better_sqlite3.node 不存在） | M0.2 中 `pnpm rebuild better-sqlite3 esbuild` 实际未对 better-sqlite3 生效（无 build 目录），prebuild-install 未被触发 | 进入 `node_modules/.pnpm/better-sqlite3@12.11.1/.../better-sqlite3` 手动 `npx prebuild-install`，成功下载 node-v127-win32-x64 预编译二进制 |

## 7. 验证记录
- `Invoke-RestMethod http://127.0.0.1:3210/api/health` → `{"status":"ok","db":"up","dbPath":"...server\\data\\remainder.db",...}` ✅
- `server/data/remainder.db` 文件已生成 ✅
