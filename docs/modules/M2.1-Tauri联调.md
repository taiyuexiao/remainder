# M2.1 Tauri 窗口与 server 联调

## 1. 任务背景
M0.2 搭好了 Tauri 壳配置，但首次 `tauri dev` 编译失败（缺 C++ 构建链）。用户安装 VS Build Tools 后，本功能点完成 Tauri 窗口启动与前后端联调。

## 2. 目标
- `pnpm dev:tauri` 编译通过并打开 Remainder 桌面窗口
- 窗口内前端能正常调用本地后端 API（数据加载无报错）

## 3. 需求
- Rust 侧编译通过（tauri + global-shortcut + notification 插件）
- Webview 跨域请求 `http://127.0.0.1:3210` 不被拦截
- Windows 资源文件所需图标齐备

## 4. 产出
- `server/src/index.ts`：注册 `@fastify/cors`（`origin: true` 反射任意来源）
- `server/package.json`：新增 `@fastify/cors`
- `desktop/src-tauri/icons/`：`pnpm tauri icon` 生成的全套图标
- `desktop/src-tauri/tauri.conf.json`：bundle.icon 恢复默认路径
- `desktop/src-tauri/Cargo.lock`：thiserror 1.0.69 → 1.0.65 降级
- `icon-source.png`、`make-icon.ps1`：图标源文件与生成脚本（项目根）

## 5. 实现方案
- 构建链：VS 2022 BuildTools（VCTools 工作负载）提供 MSVC link.exe
- 图标：PowerShell System.Drawing 画 1024px 圆角方块 + 白字 R，`pnpm tauri icon` 生成全平台尺寸
- 跨域：Tauri webview 源为 `http://tauri.localhost`，Fastify 反射 Origin 头即可（本地个人应用，安全风险可接受）

## 6. 遇到的报错及解决方案
| 报错/问题 | 原因 | 解决方案 |
|-----------|------|----------|
| `link: extra operand ...` 链接失败 | ① PATH 中 Git 自带 GNU link.exe 冒充 MSVC 链接器；② 机器未装 VS Build Tools | 用户管理员终端 winget 安装 VS 2022 BuildTools（VCTools 工作负载） |
| `json-patch v3.0.1` 编译失败：`cannot determine resolution for the macro ::core::write`、PatchError/PatchErrorKind 未实现 Display | json-patch 依赖的 thiserror-impl 1.0.69 与 rustc 1.97 生成的宏代码不兼容；json-patch 已是 3.x 最新无法升级 | `cargo update -p thiserror@1.0.69 --precise 1.0.65` 降级后编译通过 |
| ``icons/icon.ico` not found`（tauri-build） | 脚手架时 bundle.icon 置空且无图标文件 | 生成 icon-source.png → `pnpm tauri icon` 生成全套 → 恢复 bundle.icon 默认配置 |
| 窗口内 "后端连接失败：Failed to fetch" | Tauri webview 源（tauri.localhost）与 127.0.0.1:3210 跨域，Fastify 无 CORS 头（浏览器 1420→3210 同源问题同样存在，之前未实测数据加载未暴露） | 后端注册 `@fastify/cors` 并 `origin: true`；验证带 Origin: http://tauri.localhost 的请求返回正确 ACAO 头 |
| winget 后台安装 Build Tools 失败（exit 5008） | 非交互会话无法弹 UAC | 改由用户在管理员 PowerShell 手动执行安装命令 |
