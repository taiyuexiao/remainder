> 状态：暂不执行，存档备用 ｜ 关联文档：`docs/research/多智能体协作调研报告.md`
> 记录时间：2026-09

## 核心观点

**别从协议层做起，从"文件即消息"做起。** 先证明价值，再上协议。

## 第一步：Spec 黑板（零基础设施，今天就能用）

场景前提：几个人 + 各自的编码 agent + 同一个 git 仓库。"agent 感知队友"不需要任何新技术：

```
项目仓库/
├── modules/
│   ├── 支付模块/
│   │   ├── SPEC.md      ← 接口契约（导出什么 API/事件/数据结构）
│   │   ├── STATUS.md    ← 状态机（doing/done/blocked + 最后更新 + 阻塞原因）
│   │   └── DECISIONS.md ← 关键取舍（为什么这么定）
│   └── 评测模块/
│       └── ...
└── AGENTS.md            ← 给所有 agent 的纪律
```

`AGENTS.md` 写死三条纪律（最关键的一步，比任何框架都重要）：

```
1. 开工前：必须读 dependencies 里列出的相邻模块的 SPEC.md + STATUS.md
2. 完工后：必须更新自己模块的 STATUS.md（进度、接口变化）
3. 接口要变：不许直接改队友的东西，在 changes/ 目录提变更提案 md
```

每个开发者的 agent（Kimi CLI / Claude Code / Cursor）每次任务时自然读这些文件——**这就是"我的 agent 扫描队友的 md 感知全局"，零协议代码**。Remainder 项目里的 `docs/modules/M*.md` 已是雏形。

## 第二步：冲突与对齐靠「提案流」，不靠实时对话

ChatDev 的核心经验 communicative dehallucination——先追问澄清再动手。落到 git 工作流：

- agent 发现接口不符 → 在 `changes/` 写提案（`CHG-YYYYMMDD-标题.md`：现状 / 建议 / 影响面）
- 队友 agent 读自己的 spec 后可**自动应答简单问题**
- 真正的变更必须人类确认合并（OpenSpec 的 proposal/apply/archive 状态机，直接照抄）

**红线：agent 只能写提案，不能直接改队友的 spec 或代码。** 守住这条，冲突降级为"提案堆积"，且 git diff 可查可回滚。

## 第三步：A2A 协议——只在跨机器/跨组织时才需要

何时需要真协议：agent 不在同一仓库/同一台机器协作时。

- 每人 agent 暴露 A2A server，AgentCard 声明三个技能：`answer_spec_question` / `review_change` / `report_status`
- 消息载体只三种：问（spec 疑问）/ 提（变更提案）/ 报（状态汇报）
- 用 A2A 的 `input_required` / `auth_required` 状态实现"agent 答不了就升级人类"

注意：**瓶颈是评审容量（review capacity）**。两三个人时 git + md + 提案流已足够，A2A 是过度设计。

## Remainder 落地顺序（按性价比）

| 优先级 | 动作 | 成本 | 价值 |
|---|---|---|---|
| 🥇 | **E2 感知**：server 加"项目目录 md 扫描器"，AI 助手页加"全局动态摘要"（各模块状态一句话 + 谁阻塞了） | 半天 | 单人即享"动态感知全局" |
| 🥈 | 项目挂 `SPEC.md` 模板（文档模块加"从模板新建"） | 1 小时 | 为协作打地基 |
| 🥉 | **E3 联机**：两台 Remainder 互联，共享只读 timeline + 知识库互查 | 2-3 天 | 任务排期对齐、知识共享 |
| 最后 | A2A 端点 + 提案仲裁台（E4） | 1 周+ | 多人多机时才做 |

## 判断标准（协作 vs 单干）

多 AI 团队比单 AI 慢（协调税真实存在），协作的价值在正确性和覆盖面，不在速度：

> **能一个超级个体闭环的任务，别拆；需要拆的（接口跨模块、知识跨人头），用 spec 黑板把对齐成本压到最低。**

## 风险红线

1. 评审容量是硬上限：agent 产出的提案必须小于人类评审带宽
2. 协议安全：agent 间 prompt injection 存在；auth_required 状态必须用起来
3. agent 间走结构化消息（执行流），人类才走消息流——别把 agent 拉进聊天群
